# 分屏标签页改造：立项评估记录

> 状态：已实现（构建通过），待最终验收
> 用途：沉淀「可能会引发的问题 / 涉及的文件改动 / 流程设计方案」，供判断风险与收益是否成正比。

---

## 一、目标回顾

像浏览器标签组一样，在多分屏（「多屏」组合标签）状态下：

- **拖出**：把某一个分屏拖到标签栏，从组合里摘出来成为一个独立标签；剩余分屏继续作为一个「多屏」组合标签。
- **拖回**：把一个独立标签拖回「多屏」组合标签，重新并入该分屏组合。

核心不变量：**同一文件同一时刻全局只有一个 pane**（拖出是「移动」不是「复制」）。

## 三、流程设计方案

### 1. 数据模型

```
layoutGroups: [ { id, root: <pane|split>, activePaneId }, … ]
activeGroupId: 当前激活组 id
layoutRoot  = computed(读激活组 root / 写激活组 root)   // 兼容层
activePaneId = computed(读激活组 activePaneId / 写激活组) // 兼容层
```

- 单 pane 组 → 标签栏渲染为「普通文件标签」。
- 多 pane 组 → 标签栏渲染为「多屏：A｜B｜…」组合标签。
- 画布只渲染**激活组**的 `paneLayouts`，切组即切换整块画布内容。

### 2. 拖出流程（多屏 → 独立标签）

```
用户按住多屏组合内某 pane 标题栏拖拽
  └ onPaneTitleDragStart: dragPaneId = paneId, dataTransfer='pane:'+paneId
拖到标签栏（标签项或空白）
  └ onGroupTabDrop / onTabBarDrop 命中 dragPaneId 分支
      └ detachPaneToOwnGroup(paneId)
          1) 从原组树摘除该 pane，折叠空 split（单子节点上移）
          2) 修正原组 activePaneId（若指向被摘 pane）
          3) 新建独立组 { root: pane, activePaneId: paneId }，插在原组之后
          4) 激活新组、focusPane(paneId)、resizeAllEditors
```

### 3. 拖回/合并流程（独立标签 → 多屏组合）

```
用户按住独立标签（组标签）拖拽
  └ onGroupTabDragStart: dragGroupId = sourceGroupId, dataTransfer='group:'+sourceGroupId
拖到目标组标签
  └ onGroupTabDrop 命中 dragGroupId 分支
      └ mergeGroupInto(targetGroupId, sourceGroupId)
          1) 目标组 root = split{ row, [目标组 root, 源组 root] }
          2) 源组从 layoutGroups 移除
          3) 激活目标组、聚焦源组激活 pane、resizeAllEditors
```

### 4. 打开文件流程

```
openFileToPane(fileType, key)
  ├ 全局已有 pane → findPaneByFileAnyGroup 命中 → 切组聚焦（复用，不新建）
  ├ 空布局         → 单 pane 写入激活组
  └ 其它           → 新建独立标签组（不再「替换激活窗口」，消除 tab 与 pane 不一致）
```

### 5. 关闭流程

```
closePane(paneId)  // 跨组
  ├ 组内移除 pane，折叠空 split
  ├ 组空 → 删除组；若为激活组则聚焦相邻组，无相邻则 resetToWelcomeState
  ├ 文件在所有组无其它 pane 引用 → 联动关闭 tab（tabs/docTabs）并释放 AI 绑定
  └ 组非空 → 修正 activePaneId
closeGroup(groupId)  // 关闭整个标签组 = 依次 closePane（任一取消则中断）
```

### 6. 持久化流程

```
watch(layoutGroups, persistLastLayout, {deep:true})
persistLastLayout → localStorage['mindmap-last-layout'] = {version:2, activeGroupIndex, groups:[{root,activePaneId}]}
restoreLastLayout（onMounted 延迟 800ms）
  ├ v1 单树 → 迁移为单组
  ├ v2     → buildPaneTree 逐组重建（缺失文件跳过并提示）
  └ focusPane 恢复激活组/激活 pane
```

## 四、可能会引发的问题

### 高影响（需重点验收）

1. **「打开文件 = 新建标签组」改变了旧版「替换当前窗口」的行为**：用户在单窗口下连续打开多个文件，会产生多个标签组而非复用同一窗口。这是标签组化的必然结果，但需确认符合预期。
2. **画布只渲染激活组**：切到非激活组时，其它组的编辑器被卸载/重建（`registerEditor` 走 ref 清理），大导图反复切组可能有重建开销与瞬时空白。
3. **拖出后原组若只剩一个 pane，自动退化为普通标签**：视觉上「多屏」前缀消失，属预期，但需确认不引起误解。
4. **`el-tree-v2` 方案若被误连带实施**：大纲的 `draggable` 拖拽排序不被 TreeV2 支持，需自行实现（详见《大纲与关联图性能优化-改动方案.md》），风险较高，建议与本次分屏改造解耦。

### 中影响

5. **`openFileToPane` 新建组后**，`switchTab` / `switchDocTab` / `orderedTabs` 等旧标签切换链路成为死代码，若后续有人在旧链路上改逻辑，易踩坑。
6. **拖拽前缀守卫**依赖 `pane:` / `group:` 字符串约定，若未来新增其它拖拽源而未加前缀，可能被 `parseDropText` 误解析为文件路径。
7. **合并为固定 `row`（左右）分屏**：拖回后方向固定为左右，暂不支持用户指定拖回方向（如上下），体验单一。
8. **布局持久化不保留各 pane 的激活状态精确位置**：`buildPaneTree` 重建会重置 pane id，恢复后每组的激活 pane 退化为组内第一个。

### 低影响

9. **死代码**：`orderedTabs`/`syncTabOrder`/`buildTabItem`/`tabOrder`/`dragTabKey` 等未清理，增加阅读负担（无运行副作用）。
10. **`resizeAllEditors` 与既有内联 resize 块重复**：`splitPane`/`swapPanes`/`reorientSplit` 内仍保留重复代码，可后续统一。

## 五、风险与收益评估

### 收益

- 实现了浏览器式标签组：多分屏可拆分为独立标签、可拖回合并，符合直觉，提升多文件并行的管理效率。
- 「同文件全局唯一 pane」不变量 + computed 兼容层，**回归风险被控制在单文件内**，未改动外部组件。
- 持久化 v2 向后兼容 v1（旧版布局自动迁移），不丢历史数据。

### 风险

- 主要风险集中在**行为变更**（打开文件=新建标签组）与**画布只渲染激活组**两点，属交互/性能取舍，需真实验收。
- 拖拽交互路径较多（拖出/拖回/排序/文件/换位/重定向），且依赖 `dragPaneId`/`dragGroupId` 两个全局状态，需逐路径实测。

### 结论

> 收益（标签组化、低回归面）明显大于风险；但「打开文件=新建标签组」这一行为变更、以及「拖拽多路径防误判」需在真机实测中重点验证。**建议保留本次实现，并在验收阶段重点回归：拖出、拖回、切组、关闭组、重启后布局恢复、文件树拖入分屏六条主链路。**
