# 分屏拖出独立标签页（标签组化 / 取消组合）实现方案

> 目标：像浏览器标签组一样，在多分屏（“多屏”组合标签）状态下，把某一个分屏拖到标签栏，
> 从组合里摘出来成为一个独立的标签；剩下的分屏继续作为一个“多屏”组合标签。
> 反向：把一个独立标签拖回“多屏”组合标签，重新并入该分屏组合。

---

## 1. 需要怎么做（方案概述）

当前程序的底层是一个「单棵分屏树」：

```text
layoutRoot: 一棵树
  - pane（单标签：一个文件）
  - 或 split（多屏组合：多个 pane 组成一棵树，标签栏显示为一个“多屏”组合标签）
```

也就是说，**全窗口同一时刻只有一个分屏树**。要么是单个标签（一棵树一个 pane），
要么是“多屏”组合（一棵树多个 pane），二者不能并存。

要支持“把某个分屏拖出来成为独立标签”，本质是要把底层从「一棵树」升级为「多棵树的标签组数组」：

```text
layoutGroups: [
  { id, root: 一棵分屏树, activePaneId, ... },  // 标签组 1（可能是单 pane 或 split）
  { id, root: 一棵分屏树, activePaneId, ... },  // 标签组 2
  ...
]
activeGroupId: 当前激活的标签组
```

标签栏据此渲染：每个标签组一个标签（单个文件显示文件名；多个 pane 显示“多屏：A…｜B…”）。
“拖出”就是：把一个 pane 从 A 组的树里摘掉，塞进一个新的单-pane 标签组 B；
“拖回合并”就是：把 B 组的 root 合并进 A 组的树（重新 split）。

**为什么不能只在现有 `layoutRoot` 上打补丁**：因为“拖出后既要保留剩余组合、又要保留被拖出的独立标签”，
必然要求同一时刻存在两棵独立的树，单棵树无法表达。

---

## 2. 需要改动哪些地方

### 2.1 数据结构（`src/App.vue`）

- 把 `layoutRoot = ref(null)` 改为 `layoutGroups = ref([])`，每项形如：

  ```js
  { id: 'grp-1', root: <pane|split|null>, activePaneId: '' }
  ```

- 新增 `activeGroupId = ref('')`，并派生 `activeGroup`、`activeLayoutRoot`、`activePane`。
- 当前大量直接读写 `layoutRoot.value` / `activePaneId.value` 的地方，改成读 `activeGroup.root` / `activeGroup.activePaneId`。
- 保留 `tabs`（文件标签）不变；`docTabs` 同理。标签组与文件标签的关系：
  - 单 pane 组 → 对应一个文件标签；
  - split 组 → 对应一个“多屏”组合标签（不含独立文件标签）。

### 2.2 布局遍历与渲染

- `collectPanes(node)`、`findPaneById`、`findPaneByFile` 不变（它们只针对单棵树），
  但调用方需要传入“当前组”的 root，而不是全局 `layoutRoot`。
- `paneLayouts`（由树计算每个 pane 的 x/y/w/h）改为基于 `activeGroup.root`。
- `splitterLayouts`（分割条）同理。
- 渲染标签栏：遍历 `layoutGroups`，每个组生成一个标签项；多 pane 组沿用“多屏”组合标签样式。

### 2.3 核心操作函数（都要改成“按当前组定位”）

- `openFileToPane`：已存在文件时，先在**所有组**里找，找不到再在当前组内新建/替换 pane。
- `splitPane`：改为操作 `activeGroup.root`。
- `closePane`：从 `activeGroup.root` 摘掉 pane；若组变空则删除该组；剩最后一个组时不允许关闭/不显示关闭按钮。
- `focusPane`：改为同步 `activeGroup.activePaneId`，同时 `activeGroupId` 切换时做同样的同步。
- `addEmptyPane`（已停用，暂保留逻辑供未来复用）。
- `swapPanes`、`onPaneDrop`、`onPaneTitleDragStart` 等分屏重排逻辑：全部基于 `activeGroup.root`。

### 2.4 拖出 / 拖回交互

- **拖出**：pane 标题栏已有的 `draggable` 拖拽，扩展 `onPaneTitleDragEnd` / 新增 drop 目标。
  当拖到标签栏（或标签栏上某个“多屏”组合标签之外的位置）时：
  1. 从 `activeGroup.root` 中移除该 pane（`removePaneFromTree`）。
  2. 若移除后原组还有多个 pane，保持为 split；若只剩一个，降级为单 pane 组。
  3. 用被摘出的 pane 新建一个 `{ id, root: <pane>, activePaneId: pane.id }` 标签组，插入到标签栏原位置附近。
  4. 文件标签和 `tabs` 不需要变（文件数据不变，只是承载它的组变了）。

- **拖回合并**：把一个独立标签（单 pane 组）拖到“多屏”组合标签上：
  1. 从源组取出 pane。
  2. 在目标组的 `root` 上按落点方向调用现有的 `splitPane` 逻辑（把该 pane 并入）。
  3. 删除空的源组。

### 2.5 持久化（`electron/main.js` + `electron-store`）

- 现有“上次布局”持久化只存一棵树；需扩展为存 `layoutGroups`（每组的 root + activePaneId）。
- 启动恢复时逐个重建标签组；文件缺失则跳过该组并提示。

### 2.6 AI / 工具绑定

- 目前 AI 任务绑定 `fileId`（文件路径）。标签组化后仍按 `fileId` 绑定即可，**不需要**改成组 id；
  但工具定位实例时，需要在“所有组的所有 pane”里找对应 `fileId` 的实例（或复用 `mindMapStore` 注册表）。

---

## 3. 可能会涉及到的问题

1. **改动面大、回归风险高**：`layoutRoot` / `activePaneId` 在 `App.vue` 中被引用几十处，任何一处漏改
   都会导致“操作了别的组”或“pane 找不到”。必须一次性全部切到 `activeGroup.root`，并做完整回归。

2. **标签栏与文件标签的映射会变**：现在“多屏”组合标签会隐藏所有独立文件标签；标签组化后，
   组合标签和独立文件标签可能同时存在，`orderedTabs` / `syncTabOrder` 的排序与拖拽排序逻辑要重写。

3. **关闭行为边界**：最后一个组不允许关闭；关闭组合里的某个 pane 后组内只剩一个 pane 时，
   组合标签要自动降级为单文件标签；关闭组时若组内有 AI 任务，要弹“终止/取消”。

4. **持久化兼容**：旧版本存的“单棵树”布局要能迁移为“单组”；新版本存多组后，旧版本打开要容错。

5. **性能**：标签组数量变多后，每个组都挂着一个离屏 `MindMap` 实例，内存会涨；需要实例 LRU/上限保护
  （现状已有 5 个后台实例上限，可复用思路）。

6. **拖拽判定**：pane 标题栏目前用于“组内换位/切分屏方向”，新增加“拖到标签栏=拖出”后，
  要区分拖到“标签栏”还是“组内其它 pane”，否则容易误触。

---

## 4. 整体流程

```text
1. 数据层重构
   layoutRoot(单树) → layoutGroups(树数组) + activeGroupId
   ↓
2. 兼容层
   所有读 layoutRoot/activePaneId 的地方统一改为 activeGroup.root / activeGroup.activePaneId
   （先保证单组行为与现在完全一致，验证无回归）
   ↓
3. 标签栏
   按 layoutGroups 渲染标签；多 pane 组显示“多屏”组合标签；单 pane 组显示文件标签
   ↓
4. 拖出
   pane 标题栏拖到标签栏空白/其它标签位置 → removePaneFromTree → 新建单 pane 组
   ↓
5. 拖回合并
   独立标签拖到“多屏”组合标签 → 从源组取出 pane → splitPane 并入目标组 → 删除空源组
   ↓
6. 持久化 & AI 绑定回归
   多组布局存/读；AI 按 fileId 跨组定位实例；关闭边界/内存上限兜底
   ↓
7. 打包验证
   单屏、多屏、拖出、拖回、重启恢复、AI 后台任务各测一遍
```

> 建议分两步落地：先做 1+2（纯重构、行为不变、验证无回归），再做 3~7（新交互）。
> 不要在一次提交里同时动数据结构和交互，否则出问题很难定位。
