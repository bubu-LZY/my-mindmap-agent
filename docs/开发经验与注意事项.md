# 开发经验与注意事项（沉淀）

> 目的：把这次修修补补踩过的坑、总结出的规则记下来，以后写新文件/新程序时提前规避。

---

## 一、架构层面

1. **不要用「单例 + 当前状态」承载“多实例”需求**
   本项目最初 `mindMapStore` 只有一个“当前导图”，AI 任务每次现查“当前是谁”，
   用户一切换文件就串台。教训：凡是可能“多个同时存在”的东西（文件、窗口、任务、标签组），
   第一版就要用「按 key 存实例的注册表」，而不是“当前只有一个”。

2. **分屏/标签这类“组合与拆分”需求，底层必须是多棵树**
   单棵树只能表达“一个或一组”，无法表达“一组拆出独立标签 + 剩余仍是一组”。
   做标签组之前先把数据结构定成「数组 of 树」，否则后面推倒重来代价巨大。

3. **AI 任务要发“工牌”**
   任务发起时就绑定 `fileId`（或资源 id），全程透传，工具层按 id 取实例，
   绝不中途再去读“当前”。这是防止 AI 改错文件的根。

---

## 二、渲染 / 性能层面

4. **大列表/大图要分层降级，而不是一把梭**
   - 大纲：首屏只展开前 1~2 层 + `content-visibility:auto`，别一次性渲染几千节点。
   - 关联图：节点过多时限制渲染数量、缩到很小时只画圆点不画字，并降低力导向迭代。
   - 通用原则：先保证“能交互”，再谈“完整显示”。

5. **Canvas 逐字绘制是性能杀手**
   关联图在缩小态还给每个节点画文字，会造成大量 overdraw。按缩放级别 + 节点规模动态开关文字。

6. **渲染异常要隔离**
   用 Vue `onErrorCaptured` 把单个组件的异常吃掉，避免一个 pane 崩掉拖垮整个应用。

7. **程序化赋值会污染撤销栈 / 造成重影**
   - 编辑器先以空值挂载、再程序化塞全文，CodeMirror/Quill 会把“全文写入”记成一步撤销，
     CTRL+Z 一步清空。应在组件创建时就同步初始化数据。
   - 富文本编辑器的覆盖层若被 CSS 强制透明，会露出底层原文字形成“重影”。要么隐藏原文字，
     要么让覆盖层用不透明背景遮住。

## 三、事件 / 交互层面

8. **`@onChange` 的触发时机早于 `v-model` 更新**
   用 `@onChange` 里读 `v-model` 变量做脏检测会拿到旧值，导致“有时提示、有时不提示”。
   更可靠的是直接 `watch(modelValue)`，并在程序化赋值前先更新基准值（lastApplied）。

9. **d3/force-graph 等三方库的内部状态别靠猜**
   `canvas.__zoom` 在 d3-zoom 里是「变换值」不是「缩放行为」，给它挂 `.filter()` 无效。
   需要平移/缩放时优先用库公开 API（如 force-graph 的 `centerAt()` / `zoom()`），不要侵入内部。

10. **dragenter/dragleave 会因子元素频繁触发而闪烁**
    用“计数器”抵消 enter/leave 很容易闪。更稳的是：leave 时判断 `relatedTarget` 是否仍在容器内，
    并加 150ms 防抖再隐藏覆盖层。

11. **合成拖拽上传的 `dataTransfer` 在 Chromium 里是只读的**
    `new DragEvent('drop', { dataTransfer: dt })` 不会带上文件。要 `Object.defineProperty` 注入，
    并兜底直接给 `input[type=file]` 的 `files` 赋值 + 派发 `change`。

12. **给全局 `window` 加事件监听一定要清理**
    组件卸载时移除 `mousemove/mouseup` 等，否则会内存泄漏、旧回调继续跑。

## 四、安全层面

13. **“白名单 API”不等于“沙箱”**
    给自定义工具提供带白名单的 `context.file`，但工具代码仍能直接 `import('fs')` 绕过。
    真正的隔离要放到子进程/`utilityProcess`，只暴露最小 API，跑完回收。

14. **shell 命令拼接是注入源头**
    `child_process` 默认 `shell:true` 会把 `command` 拼进 `cmd.exe`。只有明确的 `.cmd/.bat` 或
    `npm/npx/pnpm/yarn` 包装器才走 shell，其余一律 `shell:false` + 参数数组。

15. **敏感字段落盘前先想“谁还会直接读它”**
    把 `appSecret` 加密落盘后，机器人长连接模块仍按明文读同一 key，就把它读成了密文。
    加密/解密必须成对出现，所有读该 key 的地方都要同步改成解密。

16. **信任模式/免确认要有时效**
    全局“不再弹确认”应带 TTL 自动过期，避免永久关掉危险操作确认。

## 五、Markdown 与多视图统一

17. **自定义协议/引用要能“往返”**
    `[文字](mindmap-file:...)`、`[文字](mindmap-node:...)` 这种引用，转 Markdown 时要保留 href，
    转回来时要还原成带 `smm-ref` 类的原子块，否则会退化成普通文本、失去“整块删除/点击预览”。

18. **复杂结构只读，编辑统一在 Markdown**
    表格、代码块等结构在导图/大纲只读展示，点击给明确提示“请到 Markdown 模式编辑”，
    避免用户在只读位疯狂点击却不知道为什么不能改。

19. **删除操作要“整块原子”**
    引用、表格等对象删除时要么整块删，要么不删，别让用户一个字一个字删原子对象。

---

## 六、流程 / 工程

20. **大改分两步：先“无行为变化的重构”，再“加新交互”**
    一次提交里同时改数据结构和交互，出问题极难定位。先保证行为不变、验证通过，再叠加新功能。

21. **打包前必跑一次 `vite build` 验证语法**
    改完 Vue/JS 后先本地 build 一次，能快速暴露模板/脚本错误，避免打包到一半才发现。

22. **发布前 review 全局副作用**
    重点关注：全局监听是否清理、`onBeforeUnmount` 是否回收、程序化赋值是否污染撤销栈、
    加密/解密是否成对、多实例是否误用“当前状态”。
